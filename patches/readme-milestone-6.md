# MedGemma Agent — Milestone 6 (complete)

Milestone 6 in the [architecture.md](../architecture.md) build order —
**Persistent Logging + Minimal Web UI** — delivered as four patches that each
left the system fully runnable:

| Patch | Title | Core capability |
|---|---|---|
| [6.1](readme-milestone-6-1.md) | PostgreSQL persistence + append-only audit | Durable sessions, messages, and audit rows; Alembic schema ownership |
| [6.2](readme-milestone-6-2.md) | Celery + Redis worker queues | `PROCESSING_MODE=sync|queued`; inference off the request path |
| [6.3](readme-milestone-6-3.md) | Frontend + token streaming | React/Vite UI, SSE `/chat/stream`, urgency visualization |
| [6.4](readme-milestone-6-4.md) | Structured logs + JSONL audit | structlog everywhere; every transaction audited to a JSON file |

At the end of 6.x the system is the first point where structured feedback from
testers is practical: a browser user can chat, and every important
triage/model/session/job decision has an audit record.

## 6.1 — PostgreSQL persistence + append-only audit

### Package restructure

Standalone app modules were grouped into packages (`app/core/`,
`app/api/`, `app/llm/`, `app/safety/`, `app/triage/`, `app/audit/`,
`app/sessions/`, `app/routes/`, `app/prompts/`). Public names are re-exported
from each package's `__init__.py`, so caller imports are unchanged.

### What changed

- **`app/core/models.py`** — SQLModel tables: `SessionRow`, `MessageRow`
  (append-only per-session transcript, unique on `(session_id, seq)`, FK → CASCADE),
  `AuditEventRow` (immutable rows, JSONB `payload`, indexes on session and module).
- **`app/core/db.py`** — async engine (`postgresql+asyncpg`) with `NullPool`
  (fresh connection per operation, loop-safe); `async_url()` normalizes the
  `DATABASE_URL` scheme.
- **`app/sessions/postgres.py`** — `PostgresSessionStore`: full-history
  relational storage; `save()` inserts only messages past the session's
  `persisted_count` watermark with `INSERT ... ON CONFLICT DO NOTHING`.
- **Alembic** — `alembic.ini` + `alembic/` async templating targeting
  `SQLModel.metadata`; initial migration autogenerated, applied at startup by
  `app/main.py` (`alembic upgrade head`) when Postgres storage or audit is
  enabled. No hand-written DDL.
- **`app/audit/logger.py`** — `AuditLogger` ABC; `NullAuditLogger` (default
  then) and `PostgresAuditLogger` (INSERT-only, no update/delete path).
- **`app/services/chat.py`** — each turn gets a `turn_id`; audit events recorded
  per module: `safety.safety_override`, `triage.triage_result`,
  `router.routing_decision`, `specialist.specialist_output`,
  `chat.turn_completed`.
- **`app/triage/parsing.py`** — `Urgency(StrEnum)` (`emergency`/`medical`/
  `general`); the triage JSON-schema `enum` is derived from the same enum so
  constraint and response type cannot drift. `ChatResponse.urgency` is typed.

### Configuration

```text
SESSION_STORE=postgres
AUDIT_ENABLED=true                 # defaults true with SESSION_STORE=postgres
DATABASE_URL=postgresql:///medgemma-agent
```

### Verification / trade-offs

Schema created solely by `alembic upgrade head`; a live symptom turn persisted
to `sessions`/`messages` and produced all five audit rows keyed by
`session_id` + `turn_id`. 62 tests passed. The specialist note was retained in
full for audit/evaluation (later relaxed by 6.4's trimming). `AUDIT_ENABLED`
defaulted to `false` for `memory`/`redis` stores (changed in 6.4).

## 6.2 — Celery + Redis worker queues

Move chat-turn inference off the HTTP request/response cycle onto a queue.

### What changed

- **`app/worker.py`** — Celery app, `REDIS_URL` as broker + result backend,
  json serializers, `result_expires=JOB_RESULT_EXPIRE_SECONDS`,
  `worker_concurrency=JOB_CONCURRENCY` (default 1). `process_turn` task:
  `bind=True`, `autoretry_for=(TransientModelError,)` with backoff + jitter,
  `max_retries=JOB_MAX_RETRIES`. Runs the **same `run_chat_turn` path as sync
  mode** inside `asyncio.run(...)`. Error mapping: `502`/`503`/connect/timeout →
  `TransientModelError` (retried); other HTTP/non-LLM → `JobProcessingError`
  (permanent). Errors prefixed `model-server-*` for classification.
- **`app/jobs.py`** — Redis job registry (`medgemma:job:{job_id}`, same TTL as
  results) so `GET /jobs` distinguishes pending from never-existed jobs.
- **`app/services/chat.py`** — emergency branch extracted to
  `run_emergency_turn()` (shared by sync and queued mode, byte-identical).
- **`app/main.py`** — `POST /chat` dispatches on `PROCESSING_MODE`. Queued:
  safety floor runs **synchronously first** (emergency → full `200`, never
  queued); new sessions are pre-created so the returned `session_id` is the one
  the worker loads; supplied sessions validated (`410`); enqueue → `202`
  `QueuedChatResponse`. `GET /jobs/{job_id}` maps pending/processing/success/
  LLM-failure (`200`)/other-failure (`500`)/unknown (`404`). Lifespan fails fast
  if queued mode without `SESSION_STORE=redis`.
- **`app/api/schemas.py`** — `QueuedChatResponse` and `JobResponse`.

### Configuration

```text
PROCESSING_MODE=sync              # sync | queued (queued requires SESSION_STORE=redis)
JOB_RESULT_EXPIRE_SECONDS=3600
JOB_MAX_RETRIES=3
JOB_CONCURRENCY=1
```

### Verification / trade-offs

84 tests passed (live-Redis integration included). Same turn path in both modes
guarantees identical safety/triage/routing/audit behavior. `asyncio.run` per
task is safe because stores use fresh connections per operation. Cross-process
session locking remains a pre-existing gap. Out of scope: dead-letter queue,
push/websocket completion notification, concurrency above `JOB_CONCURRENCY`.

## 6.3 — Frontend + token streaming

### What changed

- **`frontend/`** — React 19 + Vite + Tailwind v4 chat UI:
  `src/types.ts`, `src/lib/api.ts` (typed client, SSE parser, queued-mode
  `waitForJob` polling, `QueuedResponse` 202 handling), `src/hooks/useChat.ts`
  (single `useReducer`), `useHealth.ts`; components `Header`, `ChatInput`,
  `MessageList`, `MessageBubble`, `Markdown` (react-markdown + remark-gfm),
  `EventTimeline` (expandable per-turn pipeline steps), `UrgencyBanner`,
  `UrgencyModal` (dismiss only via `/^accepted[a-z]{4}$/i`). Vite dev proxy
  (target `VITE_BACKEND_URL`) — no CORS needed.
- **Backend streaming** — `LLMClient.chat_stream()` (OpenAI-compatible
  `/v1/chat/completions`, `stream: true`, `enable_thinking: false`);
  `StreamExtractor` strips the `<response>` wrapper live so clients get genuine
  incremental tokens; `run_chat_turn(..., on_token=...)` + `run_chat_turn_stream()`;
  `POST /chat/stream` returns SSE `token` / `done` / `error` events, error
  mapping identical to `POST /chat`, and degrades to `202`+polling in queued mode.

### Verification

`npm run build` passes; live timing vs. Ollama: first token ~9–22 s general
(~68–141 s specialist, pipeline-bound), then a real streaming phase. Playwright
confirmed markdown, timeline expansion, and the urgency modal flow.

## 6.4 — Structured logs + JSONL audit

Structured logging everywhere and a hard audit guarantee: **no transaction
happens without an explicit audit record appended to a JSON file.**

### What changed

- **structlog 25.5.0** — every log line renders human-readably on the console
  and as one JSON object per line in `app/logs/app.jsonl`; uvicorn/celery/httpx
  flow through the same formatter. `print()`/`logging.getLogger` calls replaced
  by key/value structlog events; `session_id` / `turn_id` / `job_id` merged via
  `structlog.contextvars`.
- **`JsonFileAuditLogger`** — append-only JSONL (`AUDIT_FILE`, default
  `app/logs/audit.jsonl`), one JSON object per line, `O_APPEND` + thread lock,
  writes in `asyncio.to_thread`. **Always active** via `build_audit_logger()`
  (a `CompositeAuditLogger` that always includes the file and adds Postgres when
  `AUDIT_ENABLED`); the `NullAuditLogger` default is gone.
- **`trim_llm_payload(payload, cap)`** — deep-trims LLM-generated strings
  (triage raw output, routing content, tool calls, specialist notes, final
  replies) to `AUDIT_LLM_CAP_CHARS` (default `1000`) with a `…[+N chars
  trimmed]` marker; applied at the source and again in the JSONL sink.
- **Full audit coverage** — new `session_created`, `session_reset`,
  `job_started`, `job_enqueued`, `job_completed`, `job_failed` events on top of
  the existing turn events.
- New settings `AUDIT_FILE` and `AUDIT_LLM_CAP_CHARS` documented in
  `.env.example`.

### Tests

`tests/test_audit.py` (10 tests): JSONL append-only shape, trimming (recursive,
nested tool calls), composite fan-out + sink-failure isolation, and
no-transaction-without-audit integration for chat/emergency/reset/queued
enqueue. Full suite: **99 passed**.

## Final state (end of Milestone 6)

- **Endpoints** — `POST /chat` (sync full response / queued `202` + `job_id`),
  `POST /chat/stream` (SSE tokens), `GET /jobs/{job_id}`, `GET
  /jobs/{job_id}/events`, `DELETE /sessions/{session_id}`, `GET /health`.
- **Storage** — `memory` / `redis` / `postgres` session stores; Alembic-owned
  schema.
- **Audit** — every transaction appended to `app/logs/audit.jsonl`, mirrored to
  Postgres `audit_events` when enabled; LLM content trimmed.
- **Logging** — structlog JSONL (`app/logs/app.jsonl`) + pretty console.

## Still missing after Milestone 6

- Prescription reading, image input, guardrails, evaluation sets (Milestones 7–10)
- Dead-letter queue, push/websocket job completion notification
- Cross-process session locking
- Streaming intermediate pipeline events (only the final reply streams today)
