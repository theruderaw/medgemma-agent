# MedGemma Agent — Milestone 7 (complete)

Milestone 7 in the [architecture.md](../architecture.md) build order —
**Image Input for Visual Symptoms** — delivered as a single patch that left
the system fully runnable and fully tested offline.

At the end of 7.x a user can attach a photo of a visual symptom; triage and
the specialist note are generated by the multimodal MedGemma tier, the image
can never be dropped by routing, every stage of the pipeline streams to the
frontend live, and the SSE channel never goes silent.

---

## What changed

### Extended triage schema

- **`app/triage/parsing.py`** — `Urgency(StrEnum)` migrated globally from
  `emergency/medical/general` to **`emergency | urgent | routine | self_care`**.
  New `TriageResult` dataclass (`urgency`, `red_flags`, `text_findings`,
  `image_findings`, `reasoning`) with `to_dict()`; hardened
  `parse_triage_result()` (fence/prose tolerant, scalar coercion, malformed
  output raises instead of silently coercing).
- **`app/prompts/triage.py`** — `TRIAGE_PROMPT` (text) and `TRIAGE_VISION_PROMPT`
  (image) share `_TRIAGE_INSTRUCTIONS` and emit the same extended JSON schema;
  `triage_context_for(result)` renders the signal for Qwen's synthesis context.
- **`app/services/triage.py`** — `run_triage(message, *, image_b64=None)` +
  `triage_model_for(image)` dispatch: text → `qwen3:0.6b`, image →
  `medgemma1.5:4b`. Both calls are schema-constrained via Ollama's native
  `/api/chat` `format` parameter.
- **Frontend migration** — urgency union, banner labels (`EMERGENCY / URGENT /
  ROUTINE / SELF CARE`), modal trigger, and all test fixtures moved to the new
  values.

### Image input pipeline

- **`app/core/images.py`** — sanitization gate: base64/`data:`-URL decode,
  `IMAGE_MAX_BYTES` cap, mime allowlist matched against decoded content,
  Pillow structural verify, EXIF-stripping JPEG re-encode (quality 85),
  alpha flattened on white, downscale to `IMAGE_MAX_DIMENSION_PX`.
  `persist_image()` writes to `IMAGE_UPLOAD_DIR` keyed by `turn_id`;
  `ProcessedImage` carries `b64/mime/sha256/size_bytes/path`.
- **`app/api/schemas.py`** — `ChatRequest.image_b64/image_mime`; new
  `TriageRequest`, `TriageResponse` (+ `source: rules|text|vision`,
  `model`, `image: ImageMeta`).
- **`app/main.py`** — `POST /v1/triage`: stateless, red-flag floor
  short-circuits to a structured emergency result with zero model calls;
  image validation failures surface as `422` before any stream opens.

### Vision-aware chat turn

- **`app/services/chat.py`** — `run_chat_turn(..., image=...)`: persists the
  image, appends an `[image attached: …]` marker to the stored message,
  records an `image.image_received` audit event (metadata only), dispatches
  extended triage, and enforces the deterministic override: if the router does
  not call the specialist on an image turn, the decision is forced to
  `symptom_related` with `image_override: true` in the audit trail. The
  specialist note is generated via Ollama's native multimodal `/api/chat`
  (images array on the last user message).
- **`app/llm/client.py`** — `chat_with_images()`, `chat_with_images_stream()`
  (native `/api/chat`, NDJSON delta parsing), `triage(temperature, image_b64)`
  dispatch, shared `_attach_images()` helper.
- **`app/worker.py`** — `process_turn` accepts and reconstructs the image for
  queued mode.

### `/v1` API surface

All endpoints moved under `/v1` (`/v1/chat`, `/v1/chat/stream`, `/v1/triage`,
`/v1/jobs/{id}`, `/v1/jobs/{id}/events`, `/v1/sessions/{id}`); `/health`
stays unversioned. Frontend client paths and the Vite proxy updated to match.

### Never-silent SSE streaming

- **`run_chat_turn_stream`** rewritten: emits `start` immediately on connect,
  forwards every audit event as a `pipeline` frame, streams the MedGemma note
  as `specialist_token` frames while it is written, and emits empty `token`
  heartbeats whenever nothing else is ready (`_STREAM_HEARTBEAT_SECONDS`,
  default 2 s). The token channel flows 100% of the time.
- **`app/main.py`** — named SSE frames (`event: start|pipeline|
  specialist_token|token|done|error`); payloads keep their `type` field so
  lenient parsers keep working. Errors map to `410/502/503` inside the stream.
- **`run_chat_turn`** gained `on_event` + `on_specialist_token` callbacks;
  queued mode keeps the blocking path unchanged.
- **Frontend** — `StreamHandlers.onPipeline/onSpecialistToken/onStart`;
  `useChat` accumulates live timeline events and the clinical note (with a
  writing indicator) into the in-flight message; empty heartbeats are ignored
  for display.

### Bugs found and fixed along the way

- **Empty streamed replies** — after streaming, the assembled reply was taken
  from `StreamExtractor.finish()`, which returns `""` whenever `feed()` had
  already flushed its buffer (any response ≥ 10 chars). Streamed replies were
  stored/sent as empty strings; old tests passed only because mock replies
  were shorter than the extractor's buffer window. The reply is now assembled
  from emitted chunks plus the finisher tail.
- **Lost specialist tail** — same pattern dropped the last buffered chunk of
  the streamed note; the finisher remainder is now emitted as a final token.
- **Placeholder prefix** — the first real reply token was appended to the
  `"Assistant is thinking…"` placeholder text; the first token now replaces it.
- **Silently unmocked tests** — two image-pipeline tests were reaching real
  Ollama (30–120 s "hangs"); all model calls are mocked again, restoring the
  offline-safe contract.

## Verification

- 140 backend tests pass offline in ~2.5 s (`pytest tests/ -q`), including new
  suites: `tests/test_triage.py` (extended schema + `/v1/triage`),
  `tests/test_images.py` (sanitization gate), `tests/test_image_pipeline.py`
  (vision dispatch, persistence, routing override, worker passthrough), and
  `tests/test_streaming.py` (event ordering, heartbeats, SSE framing, error
  frames).
- `tsc --noEmit` and `vite build` clean.

## Trade-offs / out of scope

- Images ride on the current turn only — no image-based conversation memory.
- Uploads capped at 5 MB / three mimes; no DICOM; images are never returned
  to clients (metadata only in audit).
- Queued mode does not stream (unchanged): jobs poll as before.
