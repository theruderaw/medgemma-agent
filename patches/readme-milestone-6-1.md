# Milestone 6.1 — PostgreSQL persistence + append-only audit

## Package restructure

Standalone app modules were grouped into packages:

| Before | After |
|---|---|
| `app/config.py` | `app/core/config.py` |
| `app/db.py` | `app/core/db.py` |
| `app/models.py` | `app/core/models.py` |
| `app/context.py` | `app/core/context.py` |
| `app/schemas.py` | `app/api/schemas.py` |
| `app/llm.py` | `app/llm/client.py` + `app/llm/parsing.py` |
| `app/safety.py` | `app/safety/rules.py` |
| `app/triage.py` | `app/triage/parsing.py` |
| `app/audit.py` | `app/audit/logger.py` |

Public names are re-exported from each package's `__init__.py`, so imports like
`from app.llm import extract_answer`, `from app.safety import detect_emergency`,
and `from app.audit import audit` are unchanged for callers. `app/main.py`
remains the FastAPI entrypoint. Tests keep their own layout.

## What changed

### Added: PostgreSQL backend

- **`app/models.py`** — SQLModel tables: `SessionRow` (sessions),
  `MessageRow` (messages, append-only per-session transcript, unique on
  `(session_id, seq)`, FK → sessions `ON DELETE CASCADE`), and `AuditEventRow`
  (audit_events, immutable rows with JSONB `payload` and composite indexes on
  session and module). The models are the single source of truth for the schema.
- **`app/db.py`** — async engine (`postgresql+asyncpg`) with `NullPool`
  (fresh-connection-per-operation, loop-safe) and an `async_sessionmaker`.
  `async_url()` normalizes the plain `DATABASE_URL` to the asyncpg scheme;
  `create_all()` is used by tests only.
- **`app/sessions/postgres.py`** — `PostgresSessionStore`: full-history
  relational storage via `AsyncSession`. Messages are written once and never
  updated; `save()` appends only messages beyond the session's
  `persisted_count` watermark using `INSERT ... ON CONFLICT DO NOTHING`.
- **`app/sessions/models.py`** — `Session.persisted_count` watermark used by the
  Postgres store to know which messages are new.
- **`app/sessions/manager.py`** — history cap (`MAX_HISTORY_MESSAGES`) is now
  skipped for stores that `retains_full_history`; `build_store()` supports
  `SESSION_STORE=postgres`.

### Added: Alembic migrations

- **`alembic.ini`** + **`alembic/`** — async-templated Alembic setup.
  `env.py` reads `DATABASE_URL` from the app settings and targets
  `SQLModel.metadata`.
- Initial migration `6847e7fed8ba_initial_schema` autogenerated from the models
  and applied to the empty `medgemma-agent` database. There is no hand-written
  DDL — schema evolution is `alembic revision --autogenerate` + `alembic upgrade head`.
- **`app/main.py`** — lifespan runs `alembic upgrade head` programmatically
  when Postgres storage or audit is enabled (replaces the old `init_db()`).
- Tests create tables from `SQLModel.metadata.create_all` and do **not** run
  Alembic.

### Added: append-only audit logging

- **`app/audit.py`** — `AuditLogger` ABC with `NullAuditLogger` (default) and
  `PostgresAuditLogger` (persists `AuditEventRow` via `AsyncSession`). Only
  INSERTs are issued; there is no update or delete path, so records cannot be
  modified after the fact.
- **`app/services/chat.py`** — each turn gets a `turn_id`; audit events recorded
  per module:
  - `safety` → `safety_override` (red-flag escalation)
  - `triage` → `triage_result` (urgency + raw output)
  - `router` → `routing_decision` (category, reason, raw content, tool calls)
  - `specialist` → `specialist_output` (MedGemma note **retained in full**,
    plus the routing reason and model id)
  - `chat` → `turn_completed` (final response, temperature, model)
- **`app/config.py`** — `DATABASE_URL` and `AUDIT_ENABLED` settings. Audit is
  auto-enabled when `SESSION_STORE=postgres`.

### Tests

- **`tests/test_postgres.py`** — new; skipped automatically when PostgreSQL is
  unreachable at `DATABASE_URL`:
  - store roundtrip (save → load preserves all messages)
  - append-only full history (6 messages stored even when the in-memory cap is 2)
  - unknown session / reset-deletes
  - audit writes immutable rows with correct module + JSONB payload
  - audit has no update path (rows never change)

## Pydantic enums (urgency)

Urgency is now a typed `StrEnum` instead of a loose string constant:

- **`app/triage/parsing.py`** — `Urgency(StrEnum)` with `emergency` / `medical` /
  `general`. `VALID_URGENCIES` is derived from it; `parse_triage_urgency()`
  returns an `Urgency` member (raises `ValueError` on invalid input).
- **`app/prompts/triage.py`** — the JSON-schema `enum` list sent to the triage
  model is derived from `Urgency`, so the constraint and the response type
  cannot drift.
- **`app/api/schemas.py`** — `ChatResponse.urgency: Urgency | None` exposes the
  triage result as a typed field (null when triage is disabled; `emergency` on
  the hardcoded safety short-circuit).
- **`static/index.html`** — assistant messages show a color-coded urgency badge
  (red `emergency`, amber `medical`, green `general`).

## Configuration

```text
SESSION_STORE=postgres
AUDIT_ENABLED=true                 # defaults true with SESSION_STORE=postgres
DATABASE_URL=postgresql:///medgemma-agent
```

## Verification

- Schema created solely by `alembic upgrade head` against the empty
  `medgemma-agent` database (3 tables + `alembic_version`); confirmed `\dt`.
- `SESSION_STORE=postgres AUDIT_ENABLED=true` + live Ollama: a symptom turn
  persisted to `sessions`/`messages`, and produced `triage_result`,
  `routing_decision`, `specialist_output` (full note + reason + model), and
  `turn_completed` audit rows, all keyed by `session_id` + `turn_id`.
- Full suite: 62 passed (6 Postgres tests ran against the new schema; none
  invoke Alembic).

## Notes / trade-offs

- The schema now lives in `app/models.py` (SQLModel). All DDL goes through
  Alembic autogenerate — no hand-written SQL is run against the app database.
- The specialist output retains the model's full free-form note (including any
  model "reasoning" preamble) verbatim — that is intentional for audit/evaluation.
- `AUDIT_ENABLED` defaults to `false` when `SESSION_STORE` is `memory`/`redis`,
  keeping the default local run DB-free.
- The old `medgemma_agent` database is unused after this change.
